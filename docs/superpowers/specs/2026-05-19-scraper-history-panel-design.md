# Scraper Job History в ScraperPanel — дизайн

**Дата:** 2026-05-19
**Скоуп:** Список прошлых scraper-джоб в UI. Только фронтенд.

## Проблема

`ScraperPanel.tsx` показывает только последнюю джобу (`GET /api/scraper/latest/`).
Прошлые прогоны (scrape/sentiment/ABSA) не видны — нельзя посмотреть, что и
когда запускалось, чем закончилось, сколько добавило.

## Что уже есть (без изменений)

Бэкенд полностью готов:

- `GET /api/scraper/history/` → последние 10 джоб, каждая сериализована тем же
  `_serialize()`, что и `/latest/`: `id, kind, kind_label, status, params,
  products_added, reviews_added, sentiment_analyzed, error, log_tail` (последние
  15 строк), `created_at, started_at, finished_at, duration_seconds`.
- `GET /api/scraper/jobs/<id>/` — одна джоба (не используется в этой фиче).

Изменений в `backend/` нет.

## Решение (подход A)

Сворачиваемая секция **«Tariyx»** под карточкой текущей джобы в
`frontend/src/components/ScraperPanel.tsx`. Один файл, без новых зависимостей.

### Компоненты (в том же файле, рядом со `Stat` / `statusBadge`)

- **`HistorySection`** — блок-аккордеон. Заголовок-кнопка `Tariyx (N)` с
  шевроном; паттерн раскрытия — как у существующего тоггла лога
  («Logtı kórtek/jaaw»). Свёрнут по умолчанию.
- **`HistoryRow`** — строка джобы:
  - статус-бейдж — переиспользует существующую `statusBadge(status)`;
  - `kind_label`;
  - относительное время от `created_at` («5 mın aldın») — локальный хелпер
    `timeAgo(iso)` на каркалпакских подписях;
  - длительность из `duration_seconds` (если есть);
  - `+N tovar` / `+N pikir` / `+N analiz` — только те счётчики, что > 0.
  - Клик по строке → инлайн-раскрытие: `log_tail` (15 строк, уже в payload) в
    `<pre>` (стиль как существующий лог-блок) + `error` красным, если непустой.

### Data flow

- Новый стейт: `history: ScraperJob[]`, `expandedId: number | null`,
  `historyOpen: boolean`.
- Тип `ScraperJob` уже объявлен в файле — переиспользуется (payload `/history/`
  идентичен по форме).
- `fetchHistory()` — `GET ${API_URL}/scraper/history/`, кладёт в `history`.
  Ошибки глотаются (паттерн как у существующего `refresh()`).
- Триггеры вызова `fetchHistory()`:
  1. на маунте — рядом с существующим `refresh()` в первом `useEffect`;
  2. внутри существующего `refresh()`: когда статус активной джобы становится
     терминальным (`success` | `failed`) — чтобы только что завершённая попала
     в список.
- **Новых интервалов/поллинга не добавляется** — переиспользуется
  существующий polling-эффект.

### Состояния и edge-cases

- Пустая история → текст «Tariyx joq» (стиль как «Házirgeshe jumıs joq»).
- Сеть недоступна → список не обновляется, ошибка не всплывает (как `refresh`).
- Активная (running) джоба может присутствовать и в `history`, и в карточке
  сверху — не фильтруем; статус-бейдж делает дубль очевидным и информативным.
- `duration_seconds == null` (джоба не завершена) → длительность не
  показывается.

### Дизайн-язык

Существующий Aral: `panel`, `border-hairline`, `text-clay`, `bg-night`,
`font-mono` для чисел/времени. Никаких новых токенов.

## Тестирование

Фронт-тестов в проекте нет (нет рантайма для них). Верификация:

1. `pnpm lint` — чисто;
2. `pnpm build` — зелёный (TypeScript);
3. Превью-скриншот: история отрисована, строка раскрывается в лог.

## Объём

~70–90 строк в одном файле `ScraperPanel.tsx`. Без миграций, без бэка, без
новых пакетов.

## Явно вне скоупа (YAGNI)

- Полный лог джобы (есть `/jobs/<id>/`, но 15 строк хватает).
- Пагинация / больше 10 джоб.
- Отдельная страница/роут истории.
- Изменение runner.py (живой прогресс в эфире — отдельная задача).
